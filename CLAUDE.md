# CLAUDE.md

Project instructions for Claude Code in this repo: a bilingual (en / zh-tw) Hugo site on the vendored `hugo-coder` theme, deployed to GitHub Pages.

## Build & run

- Hugo extended v0.163.3 (pinned in `.github/workflows/hugo.yml`).
- Local preview: `hugo server`
- Production build, as CI runs it: `$env:HUGO_ENVIRONMENT='production'; hugo --gc --minify`
- To verify a change without touching `public/`, build into the scratchpad with `hugo -d <dir>` and inspect or diff the output HTML.
- Deploy: push to `main`; GitHub Actions builds and publishes. `public/` and `resources/` are not committed.

## Social share image (og:image / twitter:image)

The name card `static/images/og-card.jpg` (generated by `tools/make_og_card.py`) appears only when sharing the home page or the About page.

- Do not set `images` under `[params]` in `hugo.toml`. Hugo's internal `opengraph.html` / `twitter_cards.html` fall back to `site.Params.images` for any page without its own image, which puts the name card on every post.
- The card is set per page in front matter (`images: ["images/og-card.jpg"]`) in exactly four files: `content/_index.md`, `content/_index.zh-tw.md` (home), `content/about.md`, `content/about.zh-tw.md`. The `_index.md` files exist only for this; the home layout ignores their content.
- Posts show no image by default (`twitter:card` falls back to `summary`). To give a post a representative image, put it in `static/images/` and add `images: ["images/<file>"]` to the front matter of both language versions. Never use `og-card.jpg` for a post.
- Verify after a change: in a fresh build, only the four pages above should contain a `<meta ... og:image>` tag. Grep for the meta tag, not the bare string `og:image`, because `how-to-build-hugo-pages` mentions it in its body text.
